# 卡片表达与讲解交互审计

原审计日期：2026-10-02；实施更新：2026-10-03。下述主要卡片与讲解交互已纳入 p1.2 并部署到本机 r9，原审计结论保留用于解释修改动因。实际标题展开、键盘操作、长正文滚动、独立拖动手柄、关系解释、进度说明、文本编辑和三条锚定反馈已分项验收，见[本轮验收](EXPRESSION_ACCEPTANCE_2026-10-03.md)。

用户反馈：卡片内部过于简略；联结片面；各节点语言不连贯；进度存在认知壁垒；标题与内容的交互关系差。目标是类似 PPT 的标题加内容，以及点击展开细则。

后续补充：表达特性必须同时从功能、Harness 与 Prompt 工程考虑。内容组织、Agent 上下文、局部修改与表达检查的联合设计见[图文表达工作流](EXPRESSION_HARNESS_DESIGN_2026-10-02.md)。

## 判断与现有证据

反馈成立。r8 的编辑、持久化、冲突和交接检查验证了已有操作链；它们不能证明图谱讲清了论文或任务。

原 r8 的 `src/ui/ContentWorkspace.tsx` 中，标题栏的指针事件用于拖动，卡片点击用于选中，卡片自身没有标题点击展开的状态。内容主要由摘要、分节及来源组成；阅读页以完整分节呈现，自由排版按 card/article 密度呈现。当前富内容卡片正文也没有明确呈现已产出什么、验证依据和下一步的进度区域。

各节点已能保存正文，但表达链仍缺统一术语、承接语、关系解释和结论依据。需要同时修订内容组织与交互结构；仅增加字段或文字量不能作为验收完成。

## 建议设计

1. 默认卡片是一张小型讲解页：明确标题、一句核心结论、必要的要点和图例。用户不展开也能理解它在整体中的作用。要点、例子、图示可按对象需要组合，不强制所有卡片采用同一长表单。
2. 点击标题或明确的展开按钮查看细则；正文按机制、例子、证据等分层展开。查看、选中、编辑、拖动使用可区分的入口，拖动使用独立手柄。展开状态属于浏览状态，不形成内容版本；进入子图继续使用独立入口。
3. 节点之间统一名称和抽象层级，写清上一步提供什么、本节点怎样处理、下一步怎样使用。提供术语释义与全局主线；多种阅读路径共享同一内容身份。
4. 关系同时呈现类型与可阅读解释，按需要支持数据流、因果、依赖、包含、证据和反馈回路。展开关系可查看所传递的信息与适用条件；观察、推测和已验证的关系有不同证据标识。
5. 进度以已完成产出、证据、当前阻碍、下一步呈现。区分 Agent 执行状态、内容完成程度与结论验证状态；论文中的作者结果不等于本机实验完成。
6. 展开时保持关联节点可辨认，局部展开避开其他内容；长内容使用聚焦阅读区。保留用户固定排版、草稿和浏览位置，Agent 更新不主动收起正在阅读的内容。

## 表达验收

- 不展开时，用户能说明每个关键卡片的作用与核心要点。
- 沿主线阅读时，用户能解释关键输入、转换和输出，术语前后一致。
- 查看连线时，能回答为什么连接、连接表达什么以及依据是什么。
- 一个明确动作能展开正文细则，展开不要求先进入编辑界面，也不写内容历史。
- 任务状态能回答产出、依据、阻碍和下一步，不能仅依赖颜色或百分比。
- 同一材料同时提供简洁讲解、细则和原文依据，信息层次清楚；增补后仍可读。
