# 图内分组、Frame 与绘制顺序按视觉记录持久化

p1.0 已包含原生绘图和分组、完整自由内容与图内 Frame 组织。r21 源码审计发现，自由元素保存原生字段，但受管表示只回写几何、样式和标题；跨受管 / 自由元素的绘制顺序也会在重新投影时丢失。这些是原有范围的实现缺口。

使用向后兼容的可选视觉字段补齐：`Representation.canvas` 保存用户外层 `groupIds` 和 `frameId`；同一关系可在多图出现，故 `Relation.canvasByGraph` 按图保存组织信息；`Graph.sceneOrder` 保存当前图实际元素 ID 的绘制顺序。自由元素继续保留原生内容。缺少这些字段的旧项目按既有默认投影打开。

表示内部 body 与 label 继续使用派生的固有分组，外层用户分组与该固有分组分别处理。复制为新表示时分离用户分组身份，避免把复制图形重新加入原组。Frame 仍属于一张图内的原生组织，不作为多层业务子图容器。

有意义的排序以稳定元素身份描述；SDK 对 fractional index 的重编号属于投影归一化，单独发生时不形成内容变更。新增 / 删除元素不应引发所有既有元素的无意义写入，已有相对顺序需保持。只用已发布 SDK 的公开接口处理场景。

新增 `graph.patch` 和 `relation.patch` 作为现有 `canvas_apply` 的兼容操作扩展；存储按字段校验和检测过期冲突，避免排序覆盖图标题、分组覆盖关系标签。数据格式与九个 MCP 入口保持兼容。组织字段和顺序写入事务、历史和项目包；临时 presentation 不写入这些内容。

实际分组、Frame、跨类型排序、重载、复制和受保护撤销分别验收。源码路径、自动检查和真实画布操作保留各自证据，不能相互替代。
