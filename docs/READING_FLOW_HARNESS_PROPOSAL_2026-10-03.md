# 阅读主干、信息密度与研究展开：Harness 讨论稿

日期：2026-10-03。状态：设计提案；不代表新机制已实现。

用户已确认默认体验：**连续讲解主干，研究细节在对应位置就地展开**。本轮讨论以 ForecastCompass 为验收样例，不改写当前 R101 图谱或固定位置。

## 1. 核心判断与本轮核对

现有系统能保存丰富内容，但没有把内容组织成读者逐步获得理解的过程。卡片信息完整、术语在词表中存在、箭头有解释，均不能单独保证连续阅读。改进需要贯穿来源整理、讲解规划、上下文组装、信息密度、关系表达和局部布局。

本轮读取当前会话真实画布：项目 `cb904f16-a9ec-4a38-831c-d84d9a08df80`，工作副本 `bdc90254-57fe-4968-97a4-96473ca9868f`，R101，目标图 `forecastcompass-reading`。

- 当前主线是问题说明 → 原图导读 → Figure 2 → 层级记忆 → 因子 → 推理 → Agent → 修订 → 案例 → 实验 → 消融 → 启示。机制总图与符号较早出现，背景和概率评价没有独立的概念递进。
- 因子、推理、Agent 三个表示采用同样的 520×350 尺寸。内容承担的理解任务不同，几何却基本按陈列规则分配。
- 现有词表将概率分布、Brier 和 ECE 放在同一条解释里。术语有定义，但未表达读者何时需要它、何时已经获得必要前置知识。
- 当前 `expression_check` 在本轮有界读取中未报问题。源码检查关注字段、身份、来源和引用存在性，尚未提供概念引入顺序、教学承接、实验覆盖、配置一致性等检查。零问题不能作为讲解有效的证明。
- 当前实验/消融说明主要突出 GPT-5-mini / FutureX 的平均结果。完整研究阅读还需要逐周差异、其他模型/数据集设置、复现条件和证据范围的关联。
- 有界表达读取明确报告了省略项；不能把未读取的节点、关系和正文判为已审阅。本轮额外核对了当前快照的正文及原论文相关章节。

## 2. 表达单位：理解步骤

默认阅读的编排单位从单个模块卡片提升为一个“理解步骤”。理解步骤可以引用一个对象的多个分节，也可以让一个对象在不同步骤承担不同解释作用；事实和证据仍共用稳定身份。

每个步骤应在编排层回答：

1. 读者带着什么问题来到这里？
2. 理解本步需要哪些已知概念？
3. 本步新增什么概念或结论？
4. 用哪种表达最容易理解：正文、案例、关系图、对照或公式？
5. 读完后自然产生什么问题，下一步如何承接？

这些是 Agent 的讲解约束，不是要求界面显示五个表单。并非每一步都必须写一段显式过渡；连接已经清楚时避免重复叙述。

研究者可跳过已知背景，但“已浏览”不能被系统认定为“已掌握”。路线的知识前提是编排声明，不是对人的能力评估。

## 3. 三种关系分别表达

| 关系 | 回答的问题 | 建议呈现 |
| --- | --- | --- |
| 讲解关系 | 为什么先读这一段、再读下一段？ | 连续主干、简短过渡、当前位置 |
| 机制关系 | 哪部分包含哪部分，传递什么，什么时候发生？ | 局部结构图、流程、时间分界、子图 |
| 证据关系 | 哪项实验支持哪项结论，支持到什么范围？ | 就地证据入口、对照表、结果与结论关联 |

概念前置关系另有明确语义，例如理解校准之前应先理解概率预测；不能复用内建 `depends_on` 作为教学前置，因为它代表真实执行依赖。

一根普通箭头不能同时承担阅读顺序、组成关系、因果与证据支持。不同关系要有可读的动词说明，颜色只作辅助。主阅读视图只呈现当前必要关系，跨章节引用按需显示；概览视图保留整体层级。

主干负责叙事，分支负责展开，横向对照负责验证。分支可以是文本、图、表、案例或子图，不要求所有展开都是另一张图，也不要求整篇论文排成放射状思维导图。

## 4. 信息密度跟随理解任务

需要区分视觉密度和语义密度。短句也可能同时引入很多陌生概念；一张密集但条件统一的对照表则可能很容易阅读。

| 理解任务 | 密度策略 | 默认内容 |
| --- | --- | --- |
| 建立必要背景 | 放慢，少分支 | 一个问题、直白解释、贯穿案例 |
| 引入概念 | 先具体、再命名 | 例子 → 含义 → 名称/符号，定义靠近首次使用 |
| 理解机制 | 适度集中，保持关系可见 | 当前输入、动作、输出及必要的局部结构 |
| 比较实验 | 在同一视野集中 | 统一条件、指标方向、对应行列、差值 |
| 归纳意义 | 压缩已建立的知识 | 结论、支持证据、适用范围、待验证问题 |
| 复现执行 | 高密度且可查 | 参数表、数据协议、提示模板、环境记录与缺项 |

首次引入概念时，一步主要引入一至两个新概念可作为初版编辑起点，不能当作普遍认知定律或产品硬限制。更有用的密度审阅信号是：陌生术语数量、同时参与的关系、必要跨区跳转、未解释符号和比较对象能否同屏。

不通过缩小字号或删掉必要解释实现低密度。必要背景、关键机制和支撑当前结论的证据摘要默认可读；补充推导、完整结果矩阵与配置详情可以折叠。

信息分层建议为：概览 → 连续讲解 → 研究展开。切换层次改变呈现，不复制事实、不创建内容修订。缩放可以辅助定位，但不能成为查找必要解释的唯一方式。

## 5. 节点尺寸和阅读布局

节点尺寸由表达角色、可读行宽、内容量和关联结构共同决定。

- 背景与过渡优先用正文，不加多余的卡片边框。
- 概念可以用小型定义块；机制需要容纳可读关系；对照表应允许占满当前阅读宽度。
- 自动高度基于实际字体、容器宽度和内容测量。宽度使用少量可解释的层级，而不是所有节点同宽同高。
- 必要长正文按完整语义拆成连续步骤；补充细节才进入就地展开。避免用固定高度加内部滚动承载每一段主线。
- 默认阅读使用连续的主滚动容器，减少多个卡片嵌套滚动。自由画布仍保留未激活时滚动预览长文的既有能力。
- 就地展开在阅读视图中推开后续内容，保留当前段落锚点；收起回到原来的阅读位置。比较对象按需要并排，窄视图下保持比较标题和条件的对应。
- 阅读编排是派生视图；自由画布的固定位置和手动尺寸继续保留。自动布局只管理明确归系统管理的区域；需要改变保存几何时走局部布局候选与版本保护流程。

点击标题展开内容，点击正文按已有规则激活选择/编辑。阅读和展开不弹模态窗口。进入子图保留主干入口、当前步骤和返回锚点，可先在原位展示子图摘要，完整画布探索作为进一步动作。

“流式化”包含两个不同目标：阅读按理解路径连续流动；Agent 的增量生成按完整语义步骤发布。不要把逐 token 输出当成每次都重新排版整图的理由。

## 6. 同一份事实上的入门与研究阅读

共用来源、概念、方法对象、指标、实验条件、结果和声明。路线决定先后、详略和解释角度。

入门路线围绕：必要背景 → 为什么现有办法不够 → 本文核心思路 → 具体机制 → 怎样检验 → 得到什么结论。

研究展开围绕：形式定义 → 完整实验条件与结果矩阵 → 消融比较 → 不确定性/统计协议 → 复现配置 → 可检验的迁移假设。

实验结果的稳定身份至少关联：数据集、模型及角色、方法/消融条件、时间与数据划分、指标及计算约定、聚合方式、结果值、来源。配对比较需要兼容的条件；不把不同表、不同统计口径的数值直接相减。

配置由一份可引用的实验配置记录管理，各节点引用它，避免参数分别散落在多张卡片里。每个值区分：原文明确报告、代码核实、本机实际采用、方案建议、尚未核实。缺项保留缺项，不补写看似合理的默认值。

消融展开按“改变了什么 → 控制了什么 → 比较结果 → 能支持的解释 → 进一步实验”组织。移除后的降幅不自动等于该模块独立的因果贡献，局部反例和逐周变化不能被平均数遮住。

## 7. ForecastCompass 的连续讲解样例

贯穿同一个选举概率预测案例，案例与作者实际评测保持来源区分。

| 步骤 | 读者问题 | 获得的理解 | 就地研究展开 |
| --- | --- | --- | --- |
| 1 | 预测未来事件究竟输出什么？ | 输出概率；一次未发生不直接证明概率判断无效；需要跨事件评价 | 候选结果、概率向量、时间截点 |
| 2 | 搜到了证据，为什么仍会预测差？ | 信号选择和把证据转为信心是不同问题 | Brier/ECE 的定义与计算口径 |
| 3 | 普通旧记录缺少什么？ | 事件答案不能自然变成下一次可用的检查原则 | 记忆基线及其适配方式 |
| 4 | FoCo 存什么？ | 同类问题复用两份手册：“看什么”“信多少”；此时引入 F、R、M | 子类别索引 s、更新轮 w、式 (2)–(3) |
| 5 | 新问题怎样使用它们？ | 归类 → 检索 → 搜当前证据 → 输出概率，结构图与案例对齐 | 式 (4)、Agent 提示、工具协议 |
| 6 | 手册怎样改进？ | 等结果揭晓 → 对照原预测与复盘 → 诊断/聚合 → 局部修订，只影响未来预测 | 分类法更新、式 (5)–(10)、附录 C 算法 |
| 7 | 哪些实验支持哪些判断？ | 主结果、静态对照、两类记忆移除各回答不同问题 | 全部条件、逐周结果、消融、统计与参数选择 |
| 8 | 研究者下一步怎么做？ | 复现需要固定条件；迁移需要重新检验 | 配置记录、缺项、EvoFore 的受控实验假设 |

完整 Figure 2 在读者已经建立预测/更新时间边界、知道 F/R 含义后出现；此前可以展示只包含当前理解步骤的小部分结构。论文顺序不是唯一讲解顺序，最终要能回到原文核对。

## 9. Harness 的工作方式

1. **来源整理**：先形成概念/符号、方法、声明、实验、结果、配置与原文锚点；缺项显式保留。
2. **讲解规划**：按读者前提形成概念前置、理解步骤、主干与分支，并标记必要/补充内容。
3. **局部生成**：每次完成一个理解步骤或一个一致的比较组，选用合适形式，再产生可追踪局部变更。
4. **编排**：测量可读尺寸，形成派生阅读布局或有限区域的候选；保护身份、固定几何和阅读锚点。
5. **审阅**：分别检查协议正确、讲解连贯、证据忠实和实际阅读体验。
6. **增量维护**：沿真实概念/声明/配置引用定位影响范围，保留未受影响内容和独立批注；读取预算不足时补读，不猜测省略项。

局部 Agent 上下文应包含：当前步骤的问题、前一步结论、当前路线已引入的概念、下一步需要承接的目标、目标正文、必要定义、相关来源/证据与配置、用户所见层级、布局边界及观察版本。

物理相邻或对象图的一跳邻居不能代替讲解上下文。术语变更沿引用索引核查；证据变更核查关联声明；配置变更核查关联结果和复现步骤。所有扩展读取仍有明确范围、预算与省略记录。

Prompt 引导 Agent：先回答当前问题，再通过案例建立含义，然后命名/形式化；过渡由上一结论引出；结果要同时说明比较条件、方向与可得结论；最后做适当归纳。不允许只逐卡填栏目再认为全文已连贯。

确定性检查适合：身份、引用、声明的概念前置顺序、符号定义/作用域、实验字段与条件匹配、配置引用一致、几何/版本保护、可测溢出。文本中未声明的术语、例子是否易懂、解释是否支持推论，需要模型结合原文审阅；最终理解效果需要真实读者验收。

本地服务继续提供轻量状态、索引、检查、测量与增量同步；内容生成和语义审阅复用当前 Codex/Claude 会话。无需增加常驻模型或每次更新全文审稿。

## 10. 增量与流式发布

- 先显示有来源和状态的讲解骨架，再按完整步骤发布；未完成部分明确为草稿。
- 在一个可读步骤内部合并文字与关系更新，避免看到孤立的半个箭头或缺定义的符号。
- 内容更新和呈现准备完成后形成可见的稳定增量；布局不随逐 token 输出持续抖动。
- 当前阅读对象保留锚点，必要时显示更新提示；不抢视口、不自动跨图。
- 状态更新通常只改状态及真实依据。术语、结构、证据或配置变化才扩展对应审阅范围。
- 批注仍绑定原对象/表示/分节/段落与观察版本；新增步骤、折叠和自动尺寸不得改用顺序编号识别反馈目标。

## 11. 验收与建议推进顺序

验收需要观察阅读行为，字段检查和 UI 点击通过不足以证明讲解质量。

- 入门路线中，声明为必要的概念与符号在使用前已解释；读者无需为主线知识打开模态弹窗或到处查词。
- 首次接触的读者能复述预测输出、F/R 分工、更新时机和防泄漏边界；记录卡住的具体步骤，先修内容或承接，再调整布局。
- 研究者能从一个结论找到对应原表、条件、逐周/平均结果及复现配置，并识别哪些参数尚未核实。
- 消融能回答移除项、控制项、方向与差值、证据覆盖范围、下一步实验，避免把组件消融扩写成所有内部步骤均已证明。
- 默认阅读保证文字可读、比较项可对照、展开后邻项有序、返回锚点稳定；视图切换不会制造事实副本。
- 一次概念或配置修正能准确定位受影响区域并保留其他内容、固定排版、相机、草稿和批注身份。

建议先用 ForecastCompass 人工做出一段连续主干及一个完整研究展开，验证上述表达方法；再将有效做法提炼为数据约束、上下文装配和自动编排。先验收讲解是否成立，再扩展通用自动布局。讨论通过前不重写主项目，后续实施仍采用独立构建及既有保护流程。
