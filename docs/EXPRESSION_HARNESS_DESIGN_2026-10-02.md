# 图文表达的 Harness 与 Prompt 设计

设计日期：2026-10-02；实施更新：2026-10-03。p1.2 已在本机 r9 实施，包含表达模型、卡片展开、编辑控件、有界上下文、确定性检查、局部操作校验及任务 prompt 组装。169 项源码测试、正式安装 Node 24 stdio 的 18 项检查及当前会话实际批注闭环通过，详见[实施计划](EXPRESSION_IMPLEMENTATION_PLAN_2026-10-02.md)、[调用工作流](EXPRESSION_AGENT_WORKFLOW.md)和[本轮验收](EXPRESSION_ACCEPTANCE_2026-10-03.md)。本文中语义缩放、完整嵌套排版和全文分页等扩展方向不因本轮增量而视为已实现。

## 产品与表达单位

产品以可持续编辑的解释性图文文档为表达单位。图谱表达关系，富文本展开论述，排版安排注意力，点击展开管理信息层次。一个语义对象可以在多处出现，标题、几何位置、展开状态和内容身份各自独立。

默认卡片呈现标题、核心结论、必要要点及按需配置的图例；标题或展开按钮进入细则。正文、图表、图片、关系说明和状态区均为可组合的内容块。支持并列、嵌套、对照、时间线、说明区域及跨区域引用，保留独立文本框和自由绘图。语义约束与阅读质量约束支持自由排版，不把所有对象强制套进相同表单。

## 四层职责

| 层次 | 职责 |
| --- | --- |
| 内容模型 | 保存论点、正文、证据、任务及有类型的关系；扩充分节/段落级稳定目标；维护统一术语、主线及多条阅读路径。 |
| 表现与交互 | 组合图文块，提供标题加正文、分层展开、语义缩放、局部聚焦及自由编辑；拖动、选择、阅读和编辑有明确入口。 |
| Harness | 为 Agent 提供合适范围的状态和上下文，协调变更、校验、预览、修订及批注回路；保护身份、证据状态和用户排版。 |
| Prompt | 指导 Agent 按读者、任务与材料组织讲解，保持术语和节点承接，选择表达形式，检查可读性与论证覆盖。 |

## Harness 工作回路

读取表达目标、全局主线和术语摘要 → 读取局部对象、关系及必要邻域 → 生成有明确理由的局部变更 → 执行确定性校验 → 按改动范围预览并检查表达 → 写入受版本保护的新修订 → 接收独立批注并组装下一轮上下文。

既有 Agent Visual Canvas 工作流已经要求稳定目标、读基线、幂等写入、固定排版保护和逐条反馈。新增表达层沿用这些规则；本机 r9 的技能、纯函数和四种表达读取模式已提供可执行的讲解维护回路。语义审稿仍由现有模型会话结合原文与实际呈现完成。

上下文包含：读者与目的、主线摘要、术语表、目标内容、相关节点和关系、来源、用户看到的内容密度/展开层级、选择位置和观察版本、观察后差异、固定排版与草稿约束。按需求裁剪邻域，并明确省略内容；跨图引用、共享对象或术语变更时沿引用索引扩展读取。

反馈目标细化为对象或文本块身份、分节/段落身份、原文选区和观察版本。共享上下文去重，每条批注独立解释和回应。不能仅把全部批注拼成一段长文字，也不能只凭坐标重建目标。

确定性检查覆盖身份/引用存在性、版本冲突、来源字段、类型约束、固定几何、正文溢出和控件可达性。含义正确、讲解充分和证据是否支持结论需要结合原文进行表达审阅；检查工具不能自动证明事实。

## Prompt 组织

1. 全局表达契约：读者、目标、主线、统一术语、关系语义、证据标签、信息层级和用户排版约束。
2. 任务说明：论文围绕问题、方法、机制、对照实验、消融和局限组织；任务进度围绕目标、里程碑、产出、验证、阻碍和下一步组织。说明指导内容覆盖，不强制每张卡片具备同样的栏目。
3. 操作说明：补充正文、解释关系、统一术语、更新进度或调整排版各有明确范围。表达变化与几何变化分别提交，普通状态变更不主动重排。
4. 表达检查：默认卡片能否独立说明其作用；节点输入能否承接上一步输出；关系为何成立；细节能否一键找到；结论、例子和来源能否区分。

要求 Agent 提交结构化修改及简短理由，并查看受影响范围的呈现。避免一段大 prompt 每次重写整张图。格式、关联和版本规则由 Harness 执行；叙事与文风由 Prompt 指导。

## 进度语义与负载

Agent 执行状态、内容完成程度和结论证据状态分别保存和呈现。已编辑、已构建、已验证、已验收对应不同事实。论文作者报告的结果保留来源，本机未复现时不能显示为本机已验证。

复用当前 Codex/Claude 会话进行生成与审阅，本地 MCP 服务默认不自行发起模型调用。普通状态更新采用轻量校验；新的主线、大幅正文变更或关系结构变化才触发表达检查。预览按需生成，仅核对相关区域；跨范围术语变化扩大核查但仍保护未受影响内容。

## 验收与实施顺序

先确定内容及表达契约、稳定反馈目标和卡片状态，再接入上下文组装及局部修改工作流，随后实现分层展开与组合排版，最后用同一篇论文和一个实际任务验证整个回路。

验收必须包含：首次生成后的主线理解；点击展开的可发现性；多条段落/关系批注的准确处理；局部改动后的术语和关系承接；进度事实与证据的对应；用户布局和草稿保护；受影响范围的预览与增量成本。既有 r8 操作链测试不能替代这些表达验收。
