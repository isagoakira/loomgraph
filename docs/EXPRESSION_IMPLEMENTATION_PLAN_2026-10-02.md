# 图文表达增量实施计划

日期：2026-10-02。实施版本 p1.2。状态：用户已授权的三路 Luna Max 分工已完成；根代理已集成、部署 r9 并完成本机表达增量验收。承接需求 D013–D017，保留既有 V1 的平台与性能门槛。

## 交付目标

同一份项目同时提供讲解卡片、全文阅读与自由图文排版。卡片默认包含标题、核心结论和要点，点击标题或明确按钮展开细则；查看、拖动、编辑和批注有可区分的操作。Agent 沿统一主线、术语与关系解释维护内容，并通过可执行的上下文组装和检查回路进行局部修订。

使用当前 ForecastCompass 材料和一个实际实施进度视图验证，不把编辑/保存通过作为讲解效果通过。论文作者结果与本机实施事实分别注明来源。文本框与图示保持自由组合，不强制所有对象采用同样栏目。

## 共享契约与兼容

- 复用 Entity、Representation、Relation、Graph、FreeElement 的稳定身份。新表达数据存于各对象的 `metadata.expression`，原摘要、分节、富文本与未知扩展字段保留。
- 对象表达包含核心结论、要点、作用、输入/输出、术语引用、证据与按需出现的进度说明。关系表达包含连接解释、传递信息、条件和来源。图表达包含读者、目标、主线、术语及 typed refs 的阅读路径。
- 内容锚点作为现有 TargetRef 的可选字段，记录分节/段落身份、原文选区及观察时视图。目标对象和观察修订仍是反馈定位依据。已有服务器和项目包应完整保留这些扩展数据。
- 标题展开属于浏览状态，按项目/副本/图/内容身份隔离；不改节点几何，不写项目历史，不把查看等同编辑。p1.3 按用户补充改为卡片内原位细则与滚动预览，保留背景关系、预览位置及用户固定位置；具体规则见 WORKSPACE_CONTROLS_2026-10-03.md。
- Harness 以纯函数实现有界上下文、表达检查、修改范围校验和 prompt 组装；复用既有读/写/反馈工具，不自行调用模型。新程序增加可发现的表达读取模式及反馈扩展上下文，旧会话可用既有工具读取相同表达数据。

## 阶段与门槛

1. E0 契约：写入共享术语与版本化表达结构，核对旧内容/锚点兼容、用户当前基线与固定位置。
2. E1 讲解交互：默认要点卡片；标题和展开按钮可点击及键盘操作；详情可滚动和关闭；绘图模式保持指针穿透；拖动只用独立手柄。
3. E2 编辑：图文正文、要点、关系与进度可保存/重开；旧草稿保持；反馈附带所见选区/分节，逐条追踪。
4. E3 Harness：全局主线/术语与局部邻域结合；按预算输出并明确截断；检查缺失关系解释、术语和输入输出承接；验证变更范围/固定位置；提供论文/任务/通用 prompt。语义审阅不宣称自动事实证明。
5. E4 真实材料：整理 ForecastCompass 为统一术语和明确承接的讲解图，保留原图、子图和用户布局；通过真实当前 MCP 维护并处理独立正文/关系反馈。实施进度以真实产出、检查和未完成项呈现。
6. E5 验收与部署：根代理审读实现、完成定向与全量源码检查、隔离生产构建、正式安装 stdio/重开/项目包测试及实际页面验证。生成新本机版本和完整哈希，保留 r8、原 4317 服务/数据及源 dist；端口和当前会话能力如实记录。
