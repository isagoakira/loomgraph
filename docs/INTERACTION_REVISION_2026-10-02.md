# 演示后的交互修订与论文验收案例

用户反馈：入口在左而操作在右、绘图栏遮挡内容且不能移动、选中后批注步骤多、卡片陈列无法表达架构、没有图片参照。原功能测试通过不等于交互验收通过。本轮以 ForecastCompass Figure 2 和方法 3.1–3.3 为实际案例。

## 本轮决定

1. 右侧面板顶部集中“总览、选中、批注、讨论、历史”。选中内容自动打开上下文操作，移除左侧导航和 SDK 左侧样式面板；外观设置收在右侧。
2. 原生绘图工具默认停靠底部，手柄可拖动，位置保存在本机并随窗口边界约束。增加“适应画面”，避免第一次打开只能看见局部。
3. 选中对象、连线、图片或多选范围后直接输入批注，一次保存或 Ctrl/⌘+Enter 即形成独立条目。按目标保留尚未保存的输入；正文首次输入时冻结目标、观察版本和图路径。批量交接仍是单独且明确的动作。
4. 架构箭头连接节点边缘，关系名称直接显示。颜色辅助区分记忆、推理、更新和原图参照；结构节点没有假运行状态。模块描述提供论文来源和用途。
5. 论文案例包含架构主图、记忆子图、修订子图与原图，使用真实持久图片资源；主图包含数据流与闭环，子图进入/返回保留相机。

## 操作路径

打开架构 → 适应画面 → 选中模块 → 在右侧直接输入并保存 → 选下一处继续 → “批注”一次交接 → 将引用贴到当前 Codex 对话 → Agent 逐条回应。

查看细节：选中带子图的模块，在右侧顶部点击“展开”；返回恢复原图。对照：主图带原图图片参照，并有完整原图子图。布局：预览候选后显式应用，固定表示保留。

## 验收门槛

- 真实浏览器中所有内容可见、无工具栏遮住主标题、拖动工具栏不增加内容修订。
- 原图资源在刷新后仍可见；主图箭头、标签和三类区域足够清晰。
- 对模块、关系、图片分别直接批注；至少两条独立条目保留精确目标和观察版本，切换选择不混串输入。
- 实际 MCP 读到批次、逐条回应并关联内容修订。不能把本地保存或交接按钮解释成 Agent 已收到。
- 版本、固定位置、跨图同一对象、子图相机及资源持久化不因界面修改退化。

## 后续独立事项

Agent 生成的布局候选目前需要完善页面自动预览事件传递；本轮不以仅 MCP 返回候选宣称已显示。关联箭头的复杂正交避障、原生 Frame、批注编号就地编辑、侧栏宽度拖动、窄窗口布局、Windows 实机验收仍需分项推进。以上不改变 V1 的稳定身份、事务和执行证据边界。

## 本轮验收结果

当前会话实际 MCP 与 Ego TaskSpace 14 完成核验，最终项目 R44。两条独立演示批注分别在 R36/R39 修改内容并在 R37/R40 回应；目标、原话、观察 R30/R31 与独立结果保留。主图固定位置、全部表示几何和原图资源保持。记忆与修订子图返回相机相同，原图视图刷新后可见，工具栏拖动不写内容版本。关系选择直接显示方向和批注输入。结构/资料不再显示任务待办状态；重复反馈入口移除，子图动作提到选中区顶部。

类型检查、138 项源码测试与隔离生产构建通过。图片默认 crop 补全不再形成伪内容修改，只有自由图片的图不再显示空图提示；子图父图与相机在切换前捕获。操作记录、截图、真实 tool 回执和项目包见[本轮记录](CURRENT_SESSION_DEMO_2026-10-02.md)。
