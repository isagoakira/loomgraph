# ForecastCompass 连续讲解验证与验收记录

日期：2026-10-03。对应方案：[阅读流与 Harness 提案](READING_FLOW_HARNESS_PROPOSAL_2026-10-03.md)。

## 结论

**表达方案通过本轮内容与交互样例验证，可以作为正式 Harness 和阅读器改造的基准。当前已安装阅读器尚未通过完整的连续阅读验收。**

八步主干能按必要背景、问题、方法、机制、证据和复现逐步展开；研究信息可在对应位置打开，表格与原图可以核查。现有阅读器虽然能读取这些内容并原位展开，但仍重复组织栏目、截断必要正文，且从子图返回会丢失阅读位置。这些是下一阶段明确要修的呈现问题。

本轮没有开展真人初学者测试，因此不能把内容审阅和浏览器检查称为“已证明任何新读者都能理解”。

## 从验证中落实的修正

1. 在首次出现 FoCo 前先讲清用途；必要主干不提前引入 s、M、z，把符号留给研究展开。
2. 解释 Agent、BASE、静态与完整 FoCo 的角色；明确 F 与 R 的更新对象和诊断—聚合—修订顺序。
3. 将原文参数与复现核实建议分列；FoCo 修订轮数不再被误读为所有基线的共同执行参数。
4. 保留平均优势及第四周 ECE 的局部反向：去 F 为 .083，完整方法为 .091。消融差值不写成可相加的独立因果收益。
5. 修复预览的目录当前位置：原先只依赖局部进入/离开事件，跳到第六步时曾停留在第五步。现在结合当前步骤位置，在滚动、尺寸变化和展开后更新；原失败保留于[初始记录](evidence/reading-flow-navigation-initial-20261003.json)。

## 实际画布验收发现

主干图 `forecastcompass-learning-pilot` 的八个表示与七条 `sequence` 关系均在 R102。关系声明为讲解递进，不被解释为算法执行依赖。

第四步原位展开时，高度从 939.08 增至 1470.72 像素，后续步骤下移约 531.64 像素，阅读滚动位置没有改变，模态窗口数量为 0。收起后恢复原高度。

从第四步进入 `forecastcompass-memory` 成功，可通过面包屑返回主干。返回保留了第四步的展开状态与主干阅读模式，但滚动位置回到 0；**返回锚点要求未满足**。

当前阅读器还会重复显示核心结论、关键要点、分节正文和关系说明；必要正文在要点中被截断，并需要再展开才能读全。全局视角控件数量较多，研究分节尚未像独立预览那样成为分别可开的局部分支。故不能用“数据已导入”代替“新阅读体验已部署”。

## 下一阶段实施优先级

1. **以理解步骤组织内容与上下文。** 正式化“当前问题、已有概念、前一步结论、下一步承接、主干正文、研究分支、来源与配置引用”的契约，并明确必要与补充信息；保留稳定身份和未知扩展字段。
2. **改造连续阅读器。** 根据背景、对照、机制、时间线、证据的任务选择文本/小图/表格；主干不截断，不重复套用栏目。研究分支独立展开，并保留段落锚点及子图返回位置。
3. **接入局部维护与反馈。** 概念、结果和配置变化沿真实引用定位影响区域；批注继续绑定对象、分节、段落、引文与观察版本。展开、滚动和阅读路线切换不形成内容修订。
4. **再做自动尺寸与有限区域编排。** 先测量实际文本与容器，再提出局部布局；保持固定几何、用户修改、相机和当前阅读位置。避免随逐 token 输出反复移动整图。
5. **完成真人验收与研究覆盖。** 首次接触者复述 F/R 分工、预测与复盘时间边界；研究者定位比较条件、消融局部差异和复现缺项。记录具体卡点，不只统计按钮点击通过率。
