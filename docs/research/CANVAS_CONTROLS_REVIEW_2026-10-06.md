# 画布控件与批量操作研究：2026-10-06

结论：控件应围绕**当前选区和操作任务**组织，分组标题应围绕**内容导航和理解**组织。当前每个组常驻“展开结构／聚焦／解散分组”的方式，把内容身份和操作菜单挤进同一窄行，导致缩小总览时文字失去阅读价值。需要改成完整标题／简短摘要、明确的结构展开入口、点击选区后的统一操作栏；区域选择应成为正常编辑路径，而不只是批注附属功能。

本文件只记录官方依据和本产品设计建议；建议不是对现有实现的验收声明。调研日期为 2026-10-06，未对同行产品进行账号内 UI 实机测试。

## 2. 对当前混合画布的具体设计

以下为本产品建议，不把它们归因给同行。

### 2.1 阅读层与操作层

- **分组阅读层**：完整标题、可读摘要／状态、紧凑展开标记。标题和摘要独立换行，按钮不能以挤压文字换取空间。边界线、空白组区域指针透明；点击标题选中该组，点击展开标记只展开下一层。
- **选区操作层**：只服务一个当前选区。显示对象数、明确范围、批注、视图动作及更多菜单；聚焦和解散不常驻每个标题。多选时单对象编辑动作退出主栏。
- **编辑层**：只有显式进入编辑后才显示文本编辑控制与变形手柄。普通阅读可选文字和滚动预览；手工具拖动越过卡片时继续平移。
- **全局工具层**：选择／框选、平移、添加、撤销以及缩放。这一层应少量、稳定。框选不能要求用户先打开批注模式。

鼠标经过只产生轻微视觉提示，不能激活编辑、改变选区、展开结构或拦截既有拖动；操作所有权来自点击、按键或明确开始的手势。选区工具栏按**屏幕像素**绘制，画布内容按世界坐标排布。

### 2.2 总览缩放

| 阅读尺度 | 常显内容 | 操作呈现 |
| --- | --- | --- |
| 总览 | 上级组标题、短摘要／状态、结构轮廓；内部文本仍保留用户展开状态 | 当前选择的工具栏；不为每组常驻长按钮 |
| 组级阅读 | 组标题、摘要、子组标题、正文与图解 | 结构展开入口和当前选区菜单 |
| 近距离编辑 | 完整文字和局部图例 | 明确点击激活后的编辑控件 |

初版先移除标题上的常驻动作，再验证总览实际字宽和碰撞。若加入最小可读字号的标题投影，只对必要层级使用屏幕尺寸标签并做重叠避让；不能无限逆缩放，把几十个标题做成相互覆盖的浮层。缩放属于观看操作，不能自动修改结构展开状态或制造内容版本。

### 2.3 面积与多选的对象范围

建议提供两个明确模式，默认保守且可预测：

1. **内容框选**：空白处拖框选可见叶对象，包括语义卡片、自由文本、图片和原生图形；默认不选背景组框，不递归选隐藏后代。面积判定应提供一致规则，如完全包含与相交切换。按 Shift 增减，Esc 清空。锁定对象显示跳过数，避免静默混入编辑操作。
2. **结构选区**：点击组标题选中组织组；“选择组内内容”明确提供直接成员／全部后代。批注可选择整个语义组，移动／整理可把组作为整体块；操作清单必须说明是否包括折叠后代。

重叠组框不应因为框选穿过父框而吞掉整片内容。父组与子项同时命中时要去重：实体移动只执行一次；正文、图例部件和原生投影不能作为重复的同一对象处理。自动布局以组织分组为单位，用户框选范围可以跨组，但不能未经明确动作改写成员归属。

“锁定”和“固定位置”分别处理：锁定限制直接编辑；固定位置保护自动排版。批量动作遇到两者都应显示对象数和实际适用范围，不能把它们当成同一开关。

### 2.4 批量动作层级

| 优先级 | 动作 | 范围和约束 |
| --- | --- | --- |
| 当前回归优先 | 框选、Shift 增减、统一选区计数、聚焦选区、区域／多目标批注、选组／选成员、关闭菜单 | 必须覆盖混合对象；不能只框到原生图形；范围标签跟实际操作一致 |
| 现有能力整合 | 批量展开／收起、解散选中的组、删除明确选择的内容、撤销 | 在适用类型上出现；结构动作与内容删除分开；不能按钮已亮却只处理首个对象 |
| 后续实施 | 整组选区拖动、对齐／分布／局部整理、按类型过滤、批量锁定／固定 | 每项需独立验收；目前尚未实现的功能不渲染成可用按钮 |

面向 agent 的批注仍保留每项独立 annotationId、原话、稳定目标和观察版本；区域框选可以把独立目标装入同一批次，不应默认合成一句模糊要求。区域本身也可作为目标，但应保存世界坐标、该时刻命中对象与可见范围。后续画布重排不得改写已经冻结的观察事实。

## 3. 最小状态模型与验收门槛

建议状态分离为 `navigation / selecting / selection-idle / dragging / editing / menu-open`。既有手势一旦开始，跨卡片或边界不更换所有者；拖动结束才显示选区栏。按钮点击必须阻止误触空白清除选区，但透明栏外不拦截画布。`Escape` 首先关闭编辑／菜单，再清空选择；不要一键破坏未保存文本。

验收应使用真实纸面案例和含富文本／图片／卡片的混合选区，至少验证：

- 25%、50%、100% 的组标题与摘要不被动作按钮挤掉；长中文标题能够换行，邻组标题不互盖。
- 626 px 窄窗口、常用大窗口中，选区栏不覆盖已选内容主标题，不越界；更多菜单可完整触达。
- 从组标题、内容空白、真实空白开始的点击／拖动区别明确；平移跨过长正文与展开标记不断开。
- 同时框选卡片、文本、插图、原生形状后计数一致；Shift 增减后批量动作的对象范围即时更新。
- 区域只命中可见对象；选择组内后代必须显式操作，并能说明折叠对象是否包含。
- 当前选区进行独立批注，每项观察版本与目标保留；总览缩放、聚焦、展开不写内容版本。
- 解散不删正文、资源或下级对象；删除与撤销只影响声明的选区，锁定／固定对象处理有明确结果。
- 框选取消、相机移动、工具切换后不残留透明遮罩；hover 不进入编辑或抢占拖动。

## 4. 边界

本研究支持“selection-first 控件整合”的产品方向，并不证明当前局部排版／多人编辑／批量几何变形已经稳定。官方 SDK 示例是实现参考，Miro／FigJam 的对象能力限制提醒我们在动作显示前做能力判定。总览标签的最小字号、区域命中规则和跨组整理都属于本产品决策，应通过实际混合画布验收再冻结。
