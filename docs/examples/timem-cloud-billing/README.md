# TiMEM Cloud 图谱计费六图

入口：<http://127.0.0.1:59480/?graph=timem-cloud-billing-flow>

这组图把一次图谱请求拆成六个阅读入口。根图负责分流，入图图解释写入后的计费分叉，查询图只走到请求、预检、业务完成和成功结算入口，资源额度与钱包图承接实际财务结算；候选报价图解释参考成本如何得到候选价，上线闭环图列出仍需核验的条件。图上箭头表示规则顺序或条件；卡片、子图和颜色是讲解结构，不是正在运行的任务或生产账单。

## 六图导航

| 图 ID | 图名 | 先看什么 | 主要结论 |
|---|---|---|---|
| `timem-cloud-billing-flow` | 太忆云 · 当前计费总流程 | 从“一次太忆云图谱请求”向右读到入图、查询、浏览三条分支 | 入图默认只记 `would_charge`；Search/QA 复用 `memory.search`；托管成本仍需单独覆盖 |
| `timem-cloud-billing-ingest` | 太忆云 · 入图模拟与真实扣费 | `write → status → switch`，再看幂等与财务扣减 | 三种入图先异步写图；默认开关关闭，启用后按 `L3 + graph_ingest` 解析真实量 |
| `timem-cloud-billing-query` | 太忆云 · 查询与结算入口 | `external-query → precheck → execute → postcheck`，再看局部失败分支 | Search/QA 各收费 1 个 `memory_search`；QA 内部检索不经过第二个收费包装器；成功出口进入 finance 子图 |
| `timem-cloud-billing-finance` | 太忆云 · 资源额度与钱包 | 四卡：`quota-use → wallet-use → receipt`，另看 `finance-shortage` | 成功请求先抵扣资源额度，再赠金、现金；真实收费看 `FinanceBill/BillingTransaction`，不足写失败账单 |
| `timem-cloud-billing-pricing` | 太忆云 · 从成本到报价 | `参考成本 C → γ → 毛利目标 → 候选账单` | 候选入图按实际成功 Token×4；最终候选 Search/QA 各 1 分（0.01 元），QA 包含内部检索 |
| `timem-cloud-billing-gates` | 太忆云 · 上线验证闭环 | 从影子账本依次走路由、预算、双账本、完整毛利检查 | 这是上线前的证据清单；它不表示生产开关、生产账单或浏览器验收已经完成 |

从根图的入图、查询或候选容量卡片进入对应子图；查询成功出口进入 finance 子图，入图的真实 debit 也直接进入 finance 子图，不经过查询的外部收费包装。回到根图后再打开“从成本到报价”，可把源码现状与候选方案分开阅读。直接使用其他图 ID 时，以当前本地 Canvas 服务实际响应为准。

## 三个口径必须分开

| 层级 | 当前可说的事实 | 触发条件或证据边界 |
|---|---|---|
| 现行源码默认 | `GRAPH_INGEST_BILLING_ENABLED=False`；入图终态记录 `would_charge=true, units=1` 但不扣钱包；Search/QA 实际各走一次 `memory.search`，默认 1 单位 | 来自 `timem-platform-backend` HEAD `fb05edbeea8fdf6034adb8b8af1a6aad7b907d72` 与仓库 YAML；不等于生产运行回执 |
| 开关启用路径 | 只有部署把 `GRAPH_INGEST_BILLING_ENABLED` 打开，入图才调用 `charge_memory_write_once(level=L3, source=graph_ingest)`；当前仓库配置无 `graph_ingest` source 覆盖，回退 `L3=3` `memory_add`/任务 | 生产环境变量、挂载 YAML、active plan、钱包余额仍需部署侧确认 |
| 最终候选定价 | Search 1 分/次；QA 1 分/次且包含内部检索；入图候选按实际成功 Token×4，并另行考虑容量费 | 来自完整推导版参考会话；尚未改生产计费配置。旧草案的 QA 2 分已被替代 |

金额和资源单位不是同一层：`memory_add` / `memory_search` 是源码资源单位，钱包使用的人民币分和套餐赠额要由财务配置决定。资源包抵扣也不等于本次新增现金收入。

## 核心数字

- 入图：三种入口都返回 `202`；`completed` / `completed_with_errors` 才进入当前入图计费资格；开关启用时按任务解析为 3 个 `memory_add`（当前仓库默认配置路径）。
- 查询：`/graph/search` = 1 个 `memory_search`；`/graph/qa` = 1 个 `memory_search`。QA 先内部取子图，内部调用不再收费；空图成功返回仍走一次外部 QA 计费。
- 扣减：资源包 → `balance_gift_credits` → `balance_credits`。余额不足写 `status=failed,total_amount=0` 失败账单并返回 402。
- 入图原子性：写图和财务扣费跨 Neo4j、Redis、财务数据库，扣费失败不会自动删除已写图；财务提交后 usage 统计失败会释放计费幂等键，存在重试重复扣费风险。
- 限制：文档最多 120 chunks、并发默认 4/上限 8；表最多 10 行；Search/QA 文本最长 400 字符、`limit` 1–50、`hops=1`；QA context 2500 字符、history 800、最多 10 facts、输出最多 512 tokens、LLM 不重试。

## 候选算术（参考会话，不是现网账单）

以下数字来自完整推导版的候选模型，用来说明价格公式的数量级。它们没有改动源码配置，也没有把模型部分毛利当成平台已经获得的毛利。

- 典型文档块参考成本 `C=0.00082` 元；候选按 4 倍计为 `0.00328` 元/块，40 块为 `0.1312` 元（13.12 分），120 块为 `0.3936` 元。别名、融合、冲突判断、失败重试和固定容量成本仍需单独归属。
- 压力参数 `γ=1.5`、目标模型毛利 `g=55%` 时，`k ≥ γ/(1−g)=1.5/0.45=3.33`，候选取 `k=4`。`1−γ/k=62.5%` 是模型部分的压力测算，不是平台完整交付毛利。
- QA 参考预算为输入 8192、输出 512、查询向量 1024 Token：参考成本 `0.00256` 元；乘 `γ=1.5` 得压力成本 `0.00384` 元。最终候选 QA 价格是 1 分/次（0.01 元，包含内部检索），模型部分压力毛利为 `1−0.00384/0.01=61.6%`，不含数据库、主机、支付、赠额和其他直接成本。
- 固定容量费示例取 `F=300` 元/月、`N=25` 个付费账号、目标毛利 55%、无赠额成本：`B_min=(300/25)/(1−0.55)=26.67` 元/账号·月。26.67 元只是假设参数下的月费下限示例，不是已核实的主机账单、账号数或现网报价。

## 图例与证据

- **绿色**：本地源码或仓库配置已核对。它描述实现路径，不证明生产环境已采用相同开关和 YAML。
- **棕色**：候选定价、成本公式或上线建议。它需要真实厂商账单、套餐、容量与业务批准。
- **蓝色**：在明确参数下的算术案例，例如 `γ=1.5`、目标毛利 `55%` 和 `k=4`。
- **红色**：需要补证据的风险或决策门，不代表失败已经发生。

完整证据索引见 [source-audit.md](./source-audit.md)。报告中的源码路径、行号和候选文档引用用于回到原始材料复核；生产开关、实际 active plan、厂商模型/价格版本和真实账单仍属于部署侧证据。

## 已知代码风险

1. `stats.billing.units=1` 是入图模拟标记，真实启用路径当前按 L3 回退到 3；两个数字混在对外展示里会造成计费口径误读。
2. 入图没有 HTTP 阶段的余额预检，任务先写图、再更新 Redis 终态、最后扣费；余额不足时图数据不会自动回滚，任务状态还可能随后变成 `failed`。
3. 财务扣款在同一调用链中先提交，usage 统计随后执行；统计异常释放 Redis 幂等键，重试时可能再次扣费。
4. `completed_with_errors` 当前与完整成功任务共享入图计费资格；候选方案提出按成功提交部分结算，但该规则尚未接入当前源码。
5. 生产 YAML、环境变量、active plan、钱包余额和 LLM 路由未在本地审计中读取，不能据此宣称现网售价或现网成本。

六图已在当前正式服务呈现，细则、子图、框选、独立批注、文本编辑、删除撤销及排版预览已完成实际浏览器验收。验收结论、R182内容版本、截图及流程专用排版缺口见 [acceptance.md](./acceptance.md)；生产计费、自动显示事实同步与持续局部排版不在已通过项内。
