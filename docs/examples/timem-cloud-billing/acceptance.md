## 计费结论复核

1. 入图三种入口先返回 202。默认关闭真实计费，仅记录 `would_charge`；模拟 `units=1` 不等于真实扣款。
2. 启用后走 `L3 + graph_ingest`；当前仓库配置没有该 source 覆盖，解析为 3 个 `memory_add`/任务。资源单位与人民币金额分别核对，不能表述为每块 3 分。
3. Search/QA 各走一次 `memory.search`，默认 1 个 `memory_search`；QA 内部检索不再经过外部 HTTP 收费包装器，没有第二次内部扣费。
4. 同步查询先检查额度，再执行业务，成功后复查并结算。空图成功 QA 仍满足外部收费条件，业务错误不进入成功扣款路径。
5. 结算优先级为资源额度 → 赠金 → 现金；不足时 402 与失败账单不等于成功收款。
6. 图写入、Redis 任务状态与财务提交之间没有跨系统原子事务。财务已提交而后置统计失败时，幂等键可能被释放，重试可能重复扣款。
7. 最终候选是成功入图实际 Token 参考成本×4，Search/QA 各 1 分且 QA 包含检索，容量单独覆盖。γ=1.5、55%目标毛利及26.67元容量示例均是测算参数，非现网证据。
