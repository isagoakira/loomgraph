## 用户已提出的需求

- 以 Excalidraw SDK 为候选底座，先审计需求，再确定实施方案。
- 插件式实时富图形工作区，支持 Agent 对话集成、局部指认、标记、高亮及多轮增量修改。
- 实时任务进度是核心场景；允许 Agent 主动维护、更新和展示状态。
- 同时容纳结构示意图、流程图以及两者相互嵌套的子图。
- 交互便捷、易读、操作少，并提供丰富的预览视图。
- 目标包含高自由度和自洽排版；具体布局规则及验收方式待审计。
- 简便的标注反馈与图上执行请求是第一版需求，沿用增量变更及版本留痕规则。
- 标注默认支持多位置独立批注及一次批量发送，不能把多条意图合并成无法逐条追踪的一段反馈。
- 使用范围覆盖 macOS 和 Windows 本地 Codex，并考虑 Claude Code；stdio MCP 是首选接入方式，运行负载是验收要求。
- 跨机器通过项目包迁移接续同一项目，保留图、批注和历史。
- 典型使用规模为项目几百个节点、每个子图几十个；性能验收需同时统计连线、文本、图片等原始图形元素。
- 图内对话覆盖项目、图和对象相关的批注、答复和追问，侧栏讨论与图上对象及修改相互定位。

## 已核对的 SDK 边界

基线为发布版 0.18.1，不以开发分支接口作为交付承诺。

- 可读写场景和元素、读取选择状态，订阅变化与指针事件，导航到对象，扩展侧栏及宿主界面。
- 元素有 `id`、`groupIds`、`frameId`、`customData`，可以映射外层的任务和图表对象。
- 分组支持层次信息，但 Frame 的成员管理排除其他 Frame；不能把原生 Frame 当作通用的多层子图容器。
- 不提供任务状态语义、父子任务汇总、Agent 事件传输、业务子图导航或持续约束布局。
- `applyDeltas`、`mutateElement`、`setElementRenderOverrides` 未出现在 0.18.1 的 `ExcalidrawImperativeAPI` 中。局部修改应由适配层基于发布版接口实施；临时高亮的具体方案仍需验证。

## 概念模型（采用推荐基线）

一份项目数据派生多个视图，避免在不同图里分别维护同一任务的状态。

| 对象或关系 | 含义 |
| --- | --- |
| 任务 | 一项可跟踪的工作，有状态、最近活动和结果或阻塞信息 |
| 结构对象 | 系统、模块、资料等对象，可关联任务，但不天然等于任务 |
| 流程 | 步骤与先后、依赖、分支等关系；执行状态通过明确的任务关联显示 |
| 子图 | 节点关联的另一张图，可以是结构图、流程图或混合视图 |
| 图上表示 | 同一个任务或对象在不同视图中的显示，有独立的排版位置 |

“包含”“执行依赖”“数据流”“关联说明”应具有明确类型。图上的所有箭头不能自动按同一种执行关系解释。

## 交互基线（用户委托采用推荐方案）

- 默认总览提供项目摘要、正在进行的任务、阻塞及待用户回应事项；无须展开全部节点。
- 中央画布显示当前层级，顶部面包屑提供返回父图；详情侧栏按需打开。
- 父节点显示子任务摘要、异常数量及子图缩略图。悬停可预览，显式入口可进入子图；触屏通过同一入口操作。
- 结构节点可以进入其处理流程，流程节点可以进入涉及模块的结构图。跨层引用保留明确的来源入口。
- 状态用颜色、文字及符号共同表达；同时显示最近更新时间，避免仅靠颜色识别。
- 选择对象后，浮动入口提供统一的“反馈”操作；对象身份随请求传递，标注反馈与执行请求均关联所选对象。
- 用户查看时，状态变化直接同步；普通更新不抢走视口。跟随执行和自动定位作为可切换选项。
- 提供总览、当前子图、聚焦异常、最近变化和导出预览。不同预览来自同一数据，不要求用户重复整理。

## 标注反馈（必需能力；采用精简默认设计）

主流程为“连续选中对象或框出区域 → 分别写反馈并暂存 → 汇总查看 → 一次批量发送”。只有一条时，沿用同一个发送入口。用户只需自然语言表达意图，不填写对象 ID、版本号或反馈分类。

- 复用画布的单选、多选和分组选择。已选对象旁出现一个“反馈”入口，打开轻量输入框，完成后暂存为独立批注；用户可直接选择下一个位置继续标注。
- 待发送批注以编号标记及紧凑列表显示，可定位、修改、删除或取消本次勾选；“发送这 N 条”是主要提交操作。暂存不立即通知 Agent，切换子图仍保留当前批次。
- 同一入口支持矩形区域标注，用于空白区域、整体布局、图片局部或多个对象的组合反馈。自由笔触、复杂批注工具面板及精细文字范围标注不作为初期默认功能。
- 目标对象、所在图、子图路径、基线版本由系统自动附带；区域采用画布坐标，并保留与基线的关联。必要的局部预览作为辅助上下文，对象引用仍有明确身份。
- 标注持久化在外层数据中，画布以轻量编号或标记显示；详细文字与回应按需打开，避免遮挡图表。标注数据进入项目版本记录，不依赖截图作为唯一存储。
- Agent 的回应、相关修改批次及执行请求回执与原反馈关联。发送成功和处理完成分别记录，不因点击发送就显示“已处理”。
- 草稿显示“待发送”；发送后反馈状态精简为“待处理”和“已响应”，必要时显示“需澄清”或失败提示。用户可以查看回应、定位修改及继续追问；没有逐条确认解决的强制步骤。
- 对象移动时对象标注跟随身份；对象被移除、基线过期或区域失去明确对应时保留原引用及历史视图，提示上下文变化，不自动改指其他对象。
- 同一任务在多个视图中的对应关系可用于关联查看；一次反馈仍指向用户实际选择的对象和视图，不扩大成对所有出现位置的独立请求。

对话目标优先使用用户现有 Codex 会话，并保留 Claude Code 适配。持久批注队列及完整上下文属于本地项目数据；宿主适配负责把批次引用送入会话。具体能力和送达边界见“宿主接入可行性核对”。

## 批量反馈与 Agent 上下文组装（设计基线，本机分项已验证）

独立批注是数据单位，发送批次是归组单位。每条保留原始用户文本、目标、观察时的版本及独立处理结果；批量发送不要求全部成功或全部失败。

### 上下文组织

| 层次 | 自动组装的内容 | 用途 |
| --- | --- | --- |
| 批次共享背景 | 项目身份、当前目标、相关图的简短概览、图之间的关系、提交时版本、布局和修改规则 | 让 Agent 知道本次工作所在的整体环境，避免重复传输 |
| 每条批注 | 独立 ID、用户原话、目标引用、所在视图与子图路径、标注时版本 | 保持多条意图的边界，并能逐条回复 |
| 共享对象上下文 | 去重后的对象身份、标题、类型、业务状态、结构关系和必要的画布信息 | 每条批注引用对应条目，避免同一对象在多条批注中反复展开 |
| 相关背景 | 父节点摘要、直接邻接关系、连线端点、有关子图、可选的编号局部预览 | 支持推理和排版；背景对象不自动成为可自由修改的目标 |
| 处理约束与回执要求 | 修改范围、人工固定位置、关联更新规则、逐条结果与变更关联 | 保证局部修改可检查并准确回写 |

- 基础信息从项目数据及画布选择自动读取，用户原话原样保留；截图不能作为唯一目标标识。
- 业务对象采用稳定对象 ID；图上的具体表示采用图 ID 和元素 ID。普通自由绘图元素没有业务对象时，仍可直接按图 ID 和元素 ID 指认。
- 单条批注可以指向一个对象、多个对象、一条连线或一个矩形区域。区域保存画布坐标、原版本预览及与区域有关的候选对象；“位于区域内”不等于用户已经授权改动其中所有内容。
- 连线反馈附上端点及关系类型。子图反馈附上来源路径和父节点摘要，支持跨层理解，但不默认展开全部子图。
- 排版反馈补充位置、大小、人工固定约束及相关区域预览；逻辑反馈优先补充结构和依赖关系。取用背景应围绕用户实际意图。
- 默认获取目标及必要的直接关联信息；更深的关系或原始元素内容可按需读取，避免每次把整张图的全部 JSON 和截图放进对话。
- 全部批注均有清单和完整正文记录。长批次可分段处理或按需读取正文，仍属于同一个发送批次；不能因上下文预算而无提示地漏掉条目。
- 近期用户手动调整可作为已经发生的变更提供给 Agent，明确区分现状与待执行意图，避免重复实施。

### 版本一致性

- 标注时记录用户看到的目标状态；发送时另取当前状态并检查相关对象是否变化。用户连续标注期间，其他任务仍可实时更新。
- 不强行假定一批批注来自同一版本：每条保留观察版本，提交时提供共同的当前基线和与该条相关的变化。
- 区分批注自身修订、目标内容变化、对象位置变化及无关任务更新。对象引用可跟随移动，区域反馈保留原范围；有歧义时单独标记，不依据位置猜测新目标。
- 上下文组装与图像裁切应来自一致的快照，保证结构化对象和可选预览描绘的是同一状态。

### 处理及回写

- Agent 先识别条目之间的关系，再处理。默认独立条目可以分别实施；真正存在前置依赖的条目按依赖顺序处理。
- 多条指向同一对象不等于冲突：不同字段可以同时修改；删除后再改名、相反的布局要求等冲突需要明确处理。系统能识别目标重叠，语义冲突判断仍需结合用户文本。
- 每条结果关联批注 ID，说明已做的修改或回答、受影响对象、修改批次及版本；需要澄清或失败的条目给出具体原因。
- 一条需要澄清时，只阻止它及依赖它的条目；其他明确且无依赖的条目可以继续。
- 反馈发送批次用于归组；实际修改按有关联的变更事务处理。单条批注可关联多个变更，多条相关批注也可以关联同一变更，仍分别保留处理结果。
- 一次批量处理可以产生多个项目修订，并在批次视图中显示累计结果。重新发送或重试按批次和条目标识去重，防止重复实施已生效的改动或执行请求。
- 用户可逐条查看、追问或重新打开。若撤回某条已实施修改，需要检查后续变更依赖；历史恢复规则继续适用。

### 易用性基线

用户只看到编号标记、自己的反馈文字、待发送数量及逐条结果。稳定 ID、观察版本、上下文检索、依赖排序和变更关联均由系统处理；不要求用户学习结构化协议。

### 图相关讨论（已确认）

- 讨论侧栏围绕项目、当前图或某条批注显示用户原话、Agent 答复和后续追问；点击条目可定位目标或查看关联变更。
- 追问保留原批注目标和已有讨论摘要，并补当前状态与相关变化。没有具体对象的总体意见可以关联项目或当前图。
- Agent 通过工具回写图相关回应；宿主完整聊天记录不作为侧栏数据来源。界面复用现有会话，不另起模型。
- 讨论随项目包迁移，保留来源和历史；实际宿主连接在目标机器重新关联。

## 本地部署与低负载基线（采用推荐实现方向）

Agent 与浏览器通过同一个轻量本地服务使用项目数据：

```text
Codex / Claude Code ← stdio MCP → 本地 Node 服务 ← 本机页面连接 → Excalidraw 画布
                                      ↓
                              项目、批注、变更历史
```

- TypeScript / Node 服务由 MCP 客户端启动，通过 stdio 提供项目查询、局部更新、批注上下文读取与结果回写等工具。
- 同一服务绑定本机回环地址 `127.0.0.1`，提供预构建页面、浏览器接口及事件推送。HTTP 是浏览器访问本地页面的入口；Agent 主接口保持 stdio。
- 复用普通浏览器或 Codex 内置浏览器。Excalidraw 在页面打开时加载；前端构建结果随插件交付，日常使用直接运行发布文件。
- 状态采用事件驱动的增量更新；浏览器可用 SSE / EventSource 接收更新。这里的 SSE 是页面事件连接，与 MCP 的传输方式分别设计。
- 默认按需生成局部截图和子图预览，复用缓存；当前可见图及受影响摘要优先更新。状态变化不触发全图重排，不持续导出整图。
- 界面复用已有模型会话，后台服务负责数据和通信。运行所需组件收敛到 Node 服务、浏览器和嵌入式本地存储；前端监听构建、额外模型进程、额外浏览器进程及独立数据库服务均不属于发布版常规运行步骤。
- 项目状态与历史采用嵌入式存储作为推荐方向；资源文件随项目管理，缓存可重建。具体目录和项目包格式纳入实施方案。
- 单个 MCP 连接的基础运行形态为一个 Node 服务。V1 每个本机工作副本由一个写服务持有，多个浏览器标签页可共享；第二个独立服务返回现有入口及占用状态并拒绝写入。不同副本可独立运行，同副本多客户端写协调留在后续范围。
- stdout 专用于 MCP 协议，日志写入 stderr。正常关闭以 stdio 结束及客户端断开为主要依据，清理页面连接和存储；跨平台生命周期实现避免依赖仅在 POSIX 可用的信号行为。
- Windows 支持原生运行方向，WSL 作为可选环境。客户端配置根据该主机实际安装路径生成，项目身份不依赖某台机器的绝对文件路径。

### 跨机器项目包迁移（已确认；细节采用推荐设计）

- 用户从当前项目导出一个完整项目包，在另一台机器导入后继续查看、标注和增量编辑；导出形成一个明确版本的完整快照，后台更新仍可继续。
- 项目包包含任务与结构数据、图和子图关系、Excalidraw 场景、对象及表示的稳定 ID、人工排版约束、批注与相关 Agent 回应、变更历史，以及显示这些内容必需的资源。缓存预览可重建，不作为数据完整性的前提。
- 清单记录格式版本、项目身份、导出修订与资源校验信息；数据库内容和资源必须来自一致的快照。具体采用逻辑导出还是数据库备份由实现选择，不能直接拷贝正在写入的数据库主文件而遗漏未合并的日志。
- 导入保留项目与历史身份，同时建立新的本机工作副本身份；文件引用使用项目相对路径或资源身份。绝对路径、宿主会话绑定和本机 MCP 配置按目标机器重新关联。
- 与图有关的批注及回应随项目保留；宿主完整聊天记录、凭据及可直接执行的本机会话连接不作为项目包的默认内容。恢复历史内容和重新连接现有 Agent 分别处理。
- 导入后先恢复画布与持久记录。迁移前的“正在运行”保留为带来源和时间的历史状态，待新执行器核实；导入本身不启动、重试或停止任何真实任务。待发送批注保留，已发送请求不自动再次投递。
- 目标机器已有同一项目时，默认以独立工作副本导入，提供来源修订提示。第一版不自动合并两台机器各自继续修改的历史，也不覆盖目标机器现有项目。
- 原机副本继续存在，导出不是移动或删除。接续时由用户选定继续工作的副本，导入页面清楚显示来源及导出时间。

### 低负载验收

低负载是已确认要求，具体结果尚未测量。后续分别记录：本地服务空闲 CPU / 内存、画布打开后的浏览器增量开销、更新期间峰值、预览和布局耗时，以及关闭页面和 MCP 会话后的资源释放。初始性能预算见实施计划第 14 节，在 M0 基线后固化，调整须留痕。

典型规模已按 D011 确认。实施计划确定初始固定样例为 500 个业务对象、20 张图、每图约 50 个表示、30 条跨图批注及 10,000 条历史变更；另记录连线和 Excalidraw 原始元素总数。基准覆盖静置、连续状态更新、结构增量、预览、历史查看、批注上下文组装及项目包导出 / 导入，不把尚未测量的性能写成已达成结果。

数据实时显示表示 Agent 已上报的更新能及时呈现；Agent 没有运行或没有上报时，界面保留最后活动时间。stdio 本身不保证任意宿主主动开启新一轮模型推理。

### Codex 标注适配

- 官方 Browser Annotation API 使用 `document.oai.annotation`。文档针对 DevDay 2026 及之后的桌面版本；Enterprise / Edu 当前不可用。逐方法做能力检测，通用本地标注流程保留可用。
- 本地页面可以在安全的顶层文档中注册 surface；canvas 所在宿主元素须已连接、位于 shadow DOM 外，iframe 中不支持注册。因此首选把本地页面直接打开为浏览器顶层页面。
- `registerSurface()` 的 `hitTest` 返回稳定对象 ID 及可选名称、语义角色、元数据和视口矩形；坐标由画布位置、缩放及平移换算。`renderSelection` 负责轻量选择高亮；图或视口变化后 invalidate，移除时 dispose。
- 拾取应在本地快速完成。异步 `hitTest` 有 250 ms 回退时限，并且同一时刻只允许一个在途回调；取消后仍须结束 promise，避免后续拾取被占住。
- 元数据最多六项，只支持扁平 JSON；单个字符串最多 256 字符，总序列化大小最多 2,048 bytes。因此原生附件只携带 `projectId`、`batchId`、`graphId`、`revision`、`contextRef` 等短引用，完整批注和去重上下文由 MCP 工具从同一快照读取。
- 批量独立批注由本地数据层和轻量列表管理。程序入口 `request()` 接受可见、已连接的 DOM 元素或 DOM Range，不能直接传虚拟画布对象 ID；可用批次摘要面板作为“送入对话”的目标，具体对象选择由 surface 支持。
- `request()` 必须在用户操作中同步调用。批次应提前或持续持久化，点击交接时无需先等待网络再请求原生编辑器。
- 请求 accepted 仅表示请求被接受；打开原生编辑器不等于保存或发送。原生流程仍由用户完成提交，“送入对话”和真实处理回执分开显示。第一版按钮文案及操作步数按实际适配验证，不承诺页面能自动提交宿主消息。
- 原生标注模式会截获页面点击；它用于宿主选择 / 交接，本地连续批注仍使用普通画布选择，保持暂存和批量整理容易操作。

### Claude Code 与通用接入

- channels 可在满足条件的 Claude Code 会话中投递批次 ID 和简短通知，Agent 再通过工具读取完整上下文；结果通过按条目关联的工具回写。
- channels 投递没有可直接等同于处理完成的自动回执，忙碌时事件会排队。停止等控制另按执行器真实能力验证。
- 不满足宿主主动投递条件时，反馈持久保存在本地队列，可由 Agent 工具读取；界面区分本地保存与实际交接，提供带批次引用的简短文本交接入口。不能把队列入库显示成 Agent 已收到。
- 用户批注正文按用户输入处理，图中标签、文档和导入内容属于参考上下文；读取图内容本身不扩大执行权限。

## 图上执行请求（已确认；接入能力待验证）

- 选中任务后提供继续、重试、停止请求入口，自动携带任务身份及当前运行上下文。
- 请求交给现有 Agent 或执行器处理，并关联反馈及历史记录；主状态由实际处理结果回写。
- 请求发出、被接收、实际生效是不同阶段，界面清楚显示当前进展。停止请求的接收不等于运行已经停止。
- 宿主是否支持追加消息、中断当前运行、任务级重试及其真实语义，需要实际验证。未支持的动作应明确标示，不以修改图上状态模拟控制成功。
- 普通反馈和执行请求共用对象上下文及回执展示，避免为每种操作建立不同的使用流程。

## 更新与排版基线

- Agent 通过结构化事件上报任务更新，UI 在接收到更新后刷新；Agent 未运行或未上报时显示最后更新时间，不伪造实时性。
- 单纯状态变化只更新状态和摘要，不触发整体重排。
- Agent 可以直接新增、拆分任务节点、调整关系及更新任务记录；取消或移除项目记录与停止真实运行分别记录，后者通过已确认的执行请求入口处理。
- 结构增量优先调整受影响区域，保护用户固定的位置和批注；复杂重排提供预览或明确触发入口。
- 进度优先呈现有依据的数量，例如“完成 3/8 项”。百分比、权重及父任务状态汇总规则另行审计。
- Agent 报告、执行事件和验证结果应保留来源，展示的状态不能仅依据一段模型叙述推断。
- 修改需有基线版本及历史，防止 Agent 基于旧图覆盖用户刚做的编辑；撤回、撤销与跨子图历史的边界需验证。

## 变更记录与版本管理（必需能力；细节采用默认方案）

- 持久化每次有意义的任务、结构、批注或布局变更。视口平移、鼠标移动等临时交互不形成项目内容版本。
- 每笔变更记录操作者或来源、时间、原因、受影响对象及图、基线版本、应用后版本和前后内容。Agent 的一组关联修改作为一个逻辑批次，避免历史被碎片淹没。
- 项目内容采用连续修订号，配合增量记录及定期或里程碑快照，支持重新打开后恢复当前状态，以及查看历史版本。
- 提供“最近变化”、对象变更历史及版本对比。默认展示简短摘要，需要时才打开详细记录。
- 历史恢复生成新的变更与修订，不删除后续记录。恢复任务定义或布局，不撤销已经发生的外部执行；执行结果及其来源另行保留。
- 节点身份在多轮修改、子图切换及恢复过程中保持可追踪。移除的节点保留历史身份，避免旧批注和引用意外指向其他对象。
- 过期修改先检查受影响对象：无冲突时可合并，同一内容冲突时保留双方意图并标记待处理，保护用户刚做的编辑。
- Excalidraw 的编辑撤销与项目级历史分别设计；跨子图撤销、批次撤销、状态更新是否进入编辑撤销栈，需要在稳定性验证中确定。
- 精确的保存频率、快照阈值及历史清理策略在部署和规模审计后确定，不预先承诺性能或无限历史容量。

## 稳定性验证项目

1. 状态更新不改变用户视口、固定位置及批注。
2. 同一任务在不同视图中状态一致；父图摘要在子图更新后刷新。
3. 子图进入与返回保留视口，预览与当前数据版本一致。
4. Agent 与用户交替修改时能检测过期修改，恢复后不重复应用事件。
5. 撤销行为、元素绑定及新增节点的局部排版符合规则。
6. 大图与多张缩略图的性能，以及宿主内消息传递和实时更新能力，需要实际测量。
7. 重开项目后变更记录、对象身份和版本可恢复；历史恢复形成新修订，并保留执行结果来源。
8. 用户可连续新增独立批注并一次发送；单条与批量使用同一个反馈入口，基线与对象身份无需用户填写。
9. 对象移动、子图切换及历史恢复后标注仍可追踪；过期和已删除目标不会错误指向其他对象。
10. 反馈、Agent 回应、变更批次及执行回执能互相定位；发送失败不会丢失反馈内容或误显示完成。
11. 跨子图批注、来自不同观察版本的批注仍保留准确目标和原始意图；相关上下文及预览版本一致。
12. 多条批注处理结果齐全且逐条关联；需要澄清、冲突或失败的条目不会阻断其他无依赖条目。
13. 批次重试不重复应用已完成变更；大量批注分段处理时不会丢条目或误标全批完成。
14. macOS 和原生 Windows 下 MCP 启动、页面连接、持久化与正常关闭均可用；跨客户端核心工具行为一致。
15. Codex canvas 命中和高亮在缩放、平移、对象移动及子图切换后仍对应正确对象；异步拾取取消后可继续选择。
16. 批次引用通过宿主交接后，Agent 能读取准确快照并逐条回写；API 缺失、提交取消或通道不可用时保留反馈，并准确显示交接状态。
17. 空闲服务、可见画布、更新和预览的负载分别测量；页面关闭及 stdio 结束后资源按设计释放。
18. 继续、重试、停止分别核对实际执行器回执和生效结果，协议取消、消息入队与整轮中断不混用。
19. Mac 导出 / Windows 导入及反向迁移后，图、资源、对象身份、批注目标、历史修订和人工布局一致，并可以继续产生新修订。
20. 更新期间导出的项目包来自一致快照；资源缺失、格式不兼容或包损坏能在导入提交前检测，导入失败不影响已有项目。
21. 导入不自动触发历史执行请求；旧运行状态、宿主连接和新本机工作副本身份明确区分，待发送批注及逐条处理记录可恢复。
22. 在已确认的分层规模下，查看当前子图不会反复完整加载或重排所有子图；状态更新、缩略图和批注组装的负载与延迟分别记录。
23. 图相关讨论、答复、追问和变更相互定位；迁移后原始讨论和目标仍可追踪，宿主连接重新建立。
24. 扩展类型通过登记增加对象、关系、摘要或视图；自由图形及未知扩展数据不会因投影或导入丢失。

## 审计结论与实施入口

对话范围已确认，当前没有等待用户回答的架构决策。V1 采用通用模型与自由画布、独立子图导航、局部布局、批量批注及图相关讨论；通过本地 stdio MCP 接入现有 Agent，并以项目包完成跨机接续。

完整计划已落入固定文件，领域术语和关键状态分层决定分别保存在插件子工程文档中。实施从 M0 的公开 SDK、身份、选择 / 高亮、受保护撤销、本地 stdio 和 SQLite 验证展开，再按 M1–M6 完成内核、图交互、批注、宿主、迁移和发布。当前源码与分项证据持续更新，原 V1 平台门槛保持，表达增量按 p1.2 验收。

宿主原生标注、主动通知和真实执行控制按能力分项验证；没有接口的动作准确显示当前限制。通用反馈交接、持久讨论、执行请求与真实回执仍是必需机制。

跨设备自动同步、多人实时协作、完整聊天客户端、同副本多写服务协调及任意复杂连续布局列为后续范围。当前文档完成表示需求和计划收敛，不表示功能、双平台或性能已经通过验收。
